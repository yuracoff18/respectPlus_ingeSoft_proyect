# Integraciones de rangos

Implementación basada en documentación de los propios proveedores. Las cuentas se declaran por el jugador y se consulta su información con consentimiento; no se afirma que su propiedad haya sido verificada con OAuth.

- **LoL:** [Riot Developer Portal](https://developer.riotgames.com/apis), [documentación de LoL](https://developer.riotgames.com/docs/lol). Se resuelve el Riot ID con Account-V1 y se consulta League-V4 por PUUID. La región se valida contra una lista fija. Se distingue Solo/Duo de Flex. La respuesta de clasificación no entrega un pico histórico.
- **Valorant:** [HenrikDev MMR v3](https://docs.henrikdev.xyz/valorant/api-reference/mmr), [claves y cuotas](https://github.com/Henrik-3/unofficial-valorant-api#authentication-and-rate-limits). Ofrece rango actual y pico; requiere `HENRIK_API_KEY` en el encabezado `Authorization` y no es el servicio oficial de Riot. Se limita a 30 consultas por minuto entre todos los jugadores, incluyendo intentos fallidos. Si se agota la cuota, se rechaza la consulta sin bloquear el servidor ni reintentar automáticamente. El limitador corresponde al único worker configurado en Docker.
- **CS2:** [Steam Web API](https://partner.steamgames.com/doc/webapi/ISteamUser), [FACEIT Data API](https://docs.faceit.com/docs/data-api/data/). Steam permite consultar la identidad pública de una cuenta, pero no su clasificación Premier. FACEIT devuelve nivel y Elo propios; se etiquetan como FACEIT.
- **Fortnite:** [Osirion OpenAPI](https://dev.fnapi.osirion.gg/). Se consulta la cuenta, sus rangos y la metadata de temporadas para mostrar únicamente una temporada vigente. El máximo recibido se etiqueta como pico de esa temporada.
- **Endpoint de Fortnite suministrado:** [documentación de autenticación](https://www.api-fortnite.com/fr/docs), [API Fortnite Swagger](https://prod.api-fortnite.com/swagger/index.html), `GET /api/v1/profile/ranked?displayName=...` o `?accountId=...`. Se configura `FORTNITE_API_KEY` en el servidor y se envía con `x-api-key`; `Authorization` no es el encabezado de este proveedor. La comprobación con la clave suministrada respondió `401` con `Invalid or inactive API key` tanto en rangos como en metadata de temporadas. No se ha podido validar una respuesta de rangos autenticada: el Swagger describe el endpoint pero no define su esquema de respuesta 200. Se mantiene Osirion como fuente activa mientras se resuelve el acceso. No se solicita la contraseña de Epic.
- **Rocket League:** [respuesta del proveedor Tracker Network](https://feedback.tracker.gg/t/regarding-on-development-api/65636). Su API de Rocket League no está ofrecida para este uso; no se utilizan endpoints privados ni scraping.
- **EA Sports FC:** [Community API de EA](https://www.ea.com/games/ea-sports-fc/news/pitch-notes-fc26-community-api-update). Requiere un sitio aprobado y acceso de partner; el proyecto no tiene ese acceso configurado.

Las credenciales Riot, HenrikDev, Steam y Fortnite suministradas se guardan en `Docker/.env`, excluido del repositorio. No están en el navegador, en las imágenes Docker ni en esta documentación. Docker Compose las entrega solo al backend. Las consultas de Riot tienen un límite global de 20/s y 100/2 minutos; las de HenrikDev, 30/minuto. No se reintentan automáticamente después de una denegación.

`scripts/check_provider_access.py` comprueba acceso y muestra únicamente códigos HTTP; no imprime claves ni datos de jugadores. Admite `--provider riot` para comprobar solo LoL, incluidos los endpoints de estado y League-V4, y `--provider henrik` para la metadata de Valorant. Utiliza los mismos encabezados `User-Agent` y `Accept` que el backend: la versión anterior del verificador los omitía y producía falsos rechazos 403. Con los encabezados corregidos, Steam, Riot (estado y League-V4), HenrikDev y la metadata pública de Osirion respondieron 200. HenrikDev sin clave respondió 401, confirmando que la comprobación autenticada sí valida acceso. El endpoint suministrado de Fortnite sigue respondiendo 401. `scripts/check_fortnite_access.py` comprueba además su metadata y distingue los mensajes de autenticación conocidos, sin mostrar cabeceras ni cuerpos de respuesta completos. No se inventan rangos cuando un proveedor rechaza el acceso.

La integración `RIOT_API_KEY` se utiliza únicamente para LoL. Una [Personal Key de Riot](https://developer.riotgames.com/docs/portal) admite proyectos personales o de una comunidad privada pequeña con 20 consultas/s y 100/2 minutos; el limitador existente respeta esas cuotas. El prefijo `RGAPI-` no permite determinar el tipo ni la vigencia de una clave. Las claves de desarrollo se desactivan cada 24 horas; el tipo y el estado de una clave se consultan en el portal. La integración de Valorant conserva su proveedor independiente HenrikDev.
